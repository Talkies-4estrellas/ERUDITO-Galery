### 9. SeccionEventos — fechas dinámicas desde Supabase

- **Problema:** La home mostraba "JUL" en los badges de fecha aunque los eventos ya tenían fechas actualizadas en Supabase. `mapEvento` leía `row.fecha_corta` (columna JSON estática, no actualizada por el `UPDATE ... SET fecha = fecha + INTERVAL`).
- **Fix:** `mapEvento` en `lib/db.ts` ahora deriva `fechaCorta` dinámicamente desde el campo `fecha` (timestamp):
  ```ts
  const fecha = new Date(row.fecha);
  const dia = String(fecha.getUTCDate());
  const mes = fecha.toLocaleDateString("es-MX", { month: "short", timeZone: "UTC" })
    .replace(".", "").slice(0, 3).replace(/^./, c => c.toUpperCase());
  ```
- `SeccionEventos` ya recibía datos de Supabase vía `getEventos()` en `app/page.tsx` — solo era un bug en el mapper.
- Commit: `123c7f2`

## Notas técnicas de la sesión
- Dev server siempre en `localhost:3000` — **no iniciar nuevo**
- Turbopack acumula errores de compilaciones previas en consola del browser — verificar con screenshot o `document.title`, no con `read_console_messages`
- Paginación JSX: los controles deben colocarse FUERA del ternario principal como expresión hermana `{condicion && (...)}`, no dentro de una rama del ternario sin wrapper
- `elementFromPoint` retorna null en coordenadas fuera del viewport — la "N" del browser pane es UI de Claude Code, no del app
- Error de SQL: `fecha::date + INTERVAL + ::text` falla en columna `timestamp` — usar `fecha + INTERVAL '4 months'` directamente
- Screenshots en emulación móvil (DPR 2x): el browser pane muestra solo el 62% izquierdo de la pantalla — usar `document.body.clientWidth` en JS para confirmar que no hay overflow real
- `mapEvento`: nunca leer columnas JSON estáticas para datos que se derivan de timestamps — usar el timestamp directamente con `toLocaleDateString`
