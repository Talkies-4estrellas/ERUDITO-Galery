# Sesión 10-08-2026

## Objetivo del día
Corregir el flujo de login para usuarios de prueba, simplificar el registro eliminando la confirmación por email, y crear un sistema de evaluación para artistas y empresas que solicitan acceso a la plataforma.

---

## Lo que se hizo

### Fix: AuthGuard bloqueaba sesiones de prueba
- `components/AuthGuard.tsx` — reescrito para aceptar dos tipos de sesión:
  - Sesión real de Supabase Auth (`user` del hook `useAuth`)
  - Sesión de prueba en `localStorage` (clave `erudito-perfil`)
- Antes: si no había sesión Supabase → redirigía a `/login` (bucle infinito para usuarios de prueba)
- Ahora: lee `localStorage` en un `useEffect` y permite el acceso si alguna de las dos existe

### Nueva tabla `usuarios` — registro sin confirmación de email
- SQL ejecutado en Supabase:
  ```sql
  create table public.usuarios (
    email text primary key, clave text not null,
    rol text not null check (rol in ('artista', 'comprador', 'empresa')),
    nombre, bio, especialidad, pais, slug, avatar_url, created_at
  );
  ```
- RLS: `select_publico` + `insert_publico` para anon

### Mejoras en FormAuth.tsx
- **Registro sin email**: eliminado el paso 3 "Revisa tu correo"; el registro guarda directo en `usuarios` y redirige a `/perfil`
- **Botón de ojito**: toggle mostrar/ocultar contraseña en ambos campos (contraseña y confirmar)
- **Login multi-fuente**: verifica en orden: `accesos_prueba` → `usuarios` → `solicitudes` → Supabase Auth

### Sistema de evaluación para artistas y empresas

#### Nueva tabla `solicitudes` en Supabase
```sql
create table public.solicitudes (
  id serial primary key, email text unique, clave text,
  rol text check (rol in ('artista', 'empresa')),
  nombre, bio, especialidad, pais, motivacion,
  estado text default 'pendiente' check (estado in ('pendiente', 'aprobado', 'rechazado')),
  created_at timestamptz, revisado_at timestamptz
);
```

#### Nuevo flujo de registro según rol
| Rol | Flujo |
|---|---|
| `comprador` | Registro directo → guarda en `usuarios` → `/perfil` |
| `artista` | Formulario de evaluación → guarda en `solicitudes` → pantalla "Solicitud enviada" |
| `empresa` | Formulario de evaluación → guarda en `solicitudes` → pantalla "Solicitud enviada" |

#### Nuevo formulario de evaluación (FormAuth.tsx — paso "solicitud")
Campos: nombre completo, especialidad, país, descripción/bio, motivación (requerida)  
La selección de rol ahora muestra: *"Requiere evaluación del administrador"* para artista y empresa

#### Login con solicitud pendiente o rechazada
- Estado `pendiente` → mensaje: "Tu solicitud está siendo revisada por el administrador"
- Estado `rechazado` → mensaje: "Tu solicitud fue rechazada. Contacta a ERUDITO"

#### Panel admin — sección "Solicitudes pendientes" (PanelAdmin.tsx)
- Carga todas las solicitudes con `estado = 'pendiente'` desde Supabase
- Badge numérico con el conteo de pendientes
- Tarjetas con: nombre, email, rol, especialidad, país, motivación (extracto), fecha
- **Aprobar**: inserta en `usuarios` + marca `estado = 'aprobado'` + elimina de la lista
- **Rechazar**: marca `estado = 'rechazado'` + elimina de la lista
- Toast de confirmación en ambas acciones
