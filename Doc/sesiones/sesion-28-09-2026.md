### 1. `components/RealtimeRefresh.tsx` — nuevo componente de actualización en tiempo real

**Problema:** Los cambios de datos (obras aprobadas, nuevos artistas, eventos) solo eran visibles al recargar la página manualmente.

**Solución:** Componente client invisible que suscribe a `postgres_changes` de Supabase Realtime para las tablas indicadas y llama `router.refresh()` en cada evento, forzando que los Server Components rerenderizen con datos frescos.

```tsx
"use client";
import { useEffect } from "react";
import { useRouter } from "next/navigation";
import { supabase } from "@/lib/supabase";

export default function RealtimeRefresh({ tablas }: { tablas: string[] }) {
  const router = useRouter();
  useEffect(() => {
    const canales = tablas.map((tabla) =>
      supabase.channel(`rt-${tabla}`)
        .on("postgres_changes", { event: "*", schema: "public", table: tabla }, () => {
          router.refresh();
        }).subscribe()
    );
    return () => { canales.forEach((c) => supabase.removeChannel(c)); };
  }, [tablas, router]);
  return null;
}
```

**Añadido a:**
- `app/page.tsx` → `tablas={["obras","artistas","eventos"]}`
- `app/artistas/page.tsx` → `tablas={["artistas","obras"]}`
- `app/catalogo/fisicos/page.tsx` → `tablas={["obras"]}`
- `app/catalogo/digitales/page.tsx` → `tablas={["obras"]}`
- `app/eventos/page.tsx` → `tablas={["eventos"]}`

**Requisito en Supabase:** Database → Publications → `supabase_realtime` → añadir las tablas `obras`, `artistas`, `solicitudes`, `eventos`. ✓ Usuario las añadió.

### 3. `app/api/upload/route.ts` — fix RLS en subida de imágenes de obras

**Problema:** Al subir una obra, la imagen fallaba con `new row violates row-level security policy`.

**Causa:** La ruta usaba el cliente anon (`import { supabase } from "@/lib/supabase"`), que no tiene permisos de INSERT en Storage bajo RLS.

**Fix:** Cambio a `getServerSupabase()` (service role):
```ts
// Antes:
import { supabase } from "@/lib/supabase";
// Después:
import { getServerSupabase } from "@/lib/supabase-server";
const db = getServerSupabase();
```

### 6. Nombre e imagen del artista correctos en tarjetas de obras de plataforma

**Problema A — nombre:** Las tarjetas mostraban el prefijo del email (`talkies2438`) en lugar del nombre real del artista registrado.

**Problema B — avatar:** El mismo artista tenía imágenes de perfil diferentes entre sus obras.

**Causa:** `mapFicha` en `lib/db.ts` no tenía acceso al nombre real ni al avatar; usaba `email.split("@")[0]` y `picsum.photos` con semilla = `id_obra` (distinto por obra).

**Fix A — `app/api/artista/obras/route.ts`:** Al insertar una obra, guardar nombre y avatar en la propia fila:
```ts
nombre_artista: usuario.nombre || email.split("@")[0],
avatar_artista: usuario.avatar_url || "",
```

**Fix B — `lib/db.ts` `mapFicha`:**
```ts
artista: row.artistas
  ? mapArtista(row.artistas)
  : {
      id: 0,
      nombre: row.nombre_artista || row.artista_email?.split("@")[0] || "Artista",
      vida: "", origen: "", bio: "",
      foto: row.avatar_artista || `https://picsum.photos/seed/${row.artista_email ?? row.id_obra}/400/400`,
    },
```

**Columna `avatar_artista` en DB:** Se requería `ALTER TABLE obras ADD COLUMN IF NOT EXISTS avatar_artista text;` para almacenar el avatar.

**SQL para obras existentes (ejecutar en Supabase SQL Editor):**
```sql
ALTER TABLE obras ADD COLUMN IF NOT EXISTS avatar_artista text;
UPDATE obras SET avatar_artista = u.avatar_url
  FROM usuarios u
  WHERE obras.artista_email = u.email;
```
