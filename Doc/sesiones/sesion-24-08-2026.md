## Lo que se hizo

### 1. `/app/api/perfil/imagen/route.ts` — NUEVO Route Handler
- Sube avatar o banner a Supabase Storage bucket `perfiles` usando **service role key** (sin JWT).
- Recibe `FormData`: `file` (WebP), `tipo` (`"avatar"` | `"banner"`), `clave` (email o slug).
- Carpeta de Storage: clave normalizada → `{clave}/{tipo}.webp`.
- Devuelve `{ url }` con cache-busting (`?t=Date.now()`).
- Solución al problema central: cuentas `accesos_prueba` (localStorage) nunca tienen sesión Supabase Auth → la subida directa al Storage fallaba. Con la ruta server-side y service role, el JWT es irrelevante.

### 2. `components/MiPerfilArtista.tsx`
- Eliminado `import { useAuth }` e `import { supabase }`.
- `subirImagen()` migrada a `fetch("/api/perfil/imagen", { method: "POST", body: form })`.
- `manejarImagen()`: sin guard `!user`, clave = `perfil?.email || perfil?.slug || "artista"`.
- **Zonas de upload separadas en 2 columnas** (`sm:grid-cols-2`):

## Diagnóstico y root causes

| Problema | Causa | Solución |
|---|---|---|
| Upload falla con "Inicia sesión" | `useAuth` devuelve `null` para cuentas localStorage | API route con service role — sin JWT |
| Supabase Auth 500 en artista@test.com | GoTrue v2.195.0 no puede autenticar rows de SQL puro | Cuentas añadidas a `accesos_prueba` (localStorage) |
| 23505 duplicate email en seeds | `ON CONFLICT (id)` no cubre unique en `email` | `ON CONFLICT DO NOTHING` sin columna |
| Avatar y banner superpuestos | Avatar absolute sobre el banner en zona única | Grid 2 columnas independientes |
